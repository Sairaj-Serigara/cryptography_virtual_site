01 LAB AIM & SCOPE

Aim of the Experiment

Comprehensive study, mathematical analysis, and practical execution of Elliptic Curve Digital Signature Algorithm (ECDSA) for asymmetric origin verification and integrity protection.

Primary Statement of Aim

Experiment Focus: Asymmetric Cryptography

To implement, execute, and verify the Elliptic Curve Digital Signature Algorithm (ECDSA) using the NIST P-256 (secp256r1) elliptic curve and SHA-256 cryptographic hashing via the native browser Web Cryptography API.

The experiment aims to provide undergraduate and postgraduate engineering students with hands-on insight into private scalar generation, public point derivation ($Q = d \times G$), ephemeral scalar signing, signature verification ($v \stackrel{?}{=} r$), and the strict detection of message tampering (avalanche effect).

Engineering Importance

Why ECDSA over RSA?
  • Equivalent Security with Smaller Keys: A 256-bit ECC key offers the identical security margin of a 3072-bit RSA key, significantly reducing storage, battery, and transmission bandwidth.
  • Real-World Standard: ECDSA powers Bitcoin and Ethereum blockchain transaction signing, Apple Secure Enclave, TLS 1.3 / HTTPS cipher suites, and modern military-grade digital identity cards.
  • Non-Repudiation: Provides undeniable legal and cryptographic proof that a specific sender authorized a payload without exposing their secret signing key.

02 THEORETICAL FOUNDATIONS

Cryptographic Theory of ECDSA

Comprehensive, student-oriented mathematical engineering breakdown of Elliptic Curves, Group Law, Hash Digesting, and Asymmetric Signature Proofs.

1.1 What is Cryptography?

Cryptography is the scientific discipline of protecting digital information by transforming human-readable plaintext into unintelligible ciphertext and providing mathematical guarantees of security.

Core Security Pillars in Information Engineering:
  • Confidentiality: Ensuring that unauthorized observers cannot read the message payload.
  • Integrity: Guaranteeing that data has not been altered, deleted, or inserted during transit.
  • Authenticity: Verifying the genuine origin identity of the communicating entity.
  • Non-Repudiation: Ensuring that the author of an authorized message cannot successfully deny authoring it.

1.2 Digital Signatures vs. Traditional MACs

In symmetric Message Authentication Codes (e.g., HMAC), both Alice and Bob share the exact same key. If a dispute arises, Bob cannot prove to a judge that Alice sent the message, because Bob also possesses the key and could have forged it.

Asymmetric Signature Principle

Digital signatures solve this using an asymmetric key pair:

$$\text{Signature} = \operatorname{Sign}(K_{\text{private}}, \operatorname{Hash}(M))$$ $$\text{Validation} = \operatorname{Verify}(K_{\text{public}}, \operatorname{Hash}(M), \text{Signature}) \in \{\text{True}, \text{False}\}$$

Only the holder of $K_{\text{private}}$ can forge the signature, but any entity possessing $K_{\text{public}}$ can definitively verify its authenticity.

2.1 What is Elliptic Curve Cryptography (ECC)?

Elliptic Curve Cryptography is an approach to public-key cryptography based on the algebraic structure of elliptic curves over finite fields $\mathbb{F}_p$. In modern engineering, we use curves defined by the Short Weierstrass Equation:

$$y^2 \equiv x^3 + ax + b \pmod p$$

Where $a, b \in \mathbb{F}_p$ and the discriminant condition $4a^3 + 27b^2 \not\equiv 0 \pmod p$ ensures the curve is non-singular (contains no cusps or self-intersections).

Point Addition $(P + Q = R)$

Given two distinct points $P(x_1, y_1)$ and $Q(x_2, y_2)$ on the curve, the line through $P$ and $Q$ intersects the curve at a third point. Reflecting that point across the x-axis yields point $R = P + Q$:

$$\lambda = \frac{y_2 - y_1}{x_2 - x_1} \pmod p$$ $$x_3 = \lambda^2 - x_1 - x_2 \pmod p, \quad y_3 = \lambda(x_1 - x_3) - y_1 \pmod p$$

Point Doubling $(2P = R)$

When adding a point to itself ($P = Q$), we take the tangent line to the curve at $P$:

$$\lambda = \frac{3x_1^2 + a}{2y_1} \pmod p$$ $$x_3 = \lambda^2 - 2x_1 \pmod p, \quad y_3 = \lambda(x_1 - x_3) - y_1 \pmod p$$

2.2 The Elliptic Curve Discrete Logarithm Problem (ECDLP)

The entire security of ECC relies on the one-way nature of scalar multiplication:

$$Q = d \times G = \underbrace{G + G + \dots + G}_{d \text{ times}}$$
  • Easy Direction: Given scalar $d$ and base point $G$, calculating $Q$ takes only $O(\log_2 d)$ steps using the Double-and-Add algorithm.
  • Hard Direction (ECDLP): Given public curve point $Q$ and generator $G$, computing scalar $d$ requires $O(\sqrt{n})$ operations via Pollard's Rho algorithm. For $n \approx 2^{256}$, this takes $\approx 2^{128}$ operations—impossible with all current world computing power combined!

2.3 NIST P-256 Curve Domain Parameters

A standardized elliptic curve is defined by a 6-tuple $\mathcal{T} = (p, a, b, G, n, h)$:

Prime $p$ $2^{256} - 2^{224} + 2^{192} + 2^{96} - 1$ (Generalized Mersenne Prime)
Coefficients $a = -3$, $b \in \mathbb{F}_p$ as defined in FIPS 186-5
Generator Point $G$ Fixed base curve point with coordinates $(G_x, G_y)$
Order $n$ Prime number of points in the subgroup generated by $G$
Cofactor $h$ $h = 1$ (every non-identity curve point generates the full group)
A

ECDSA Signature Generation Algorithm

Executed by the Signer (Alice) using her Private Key $d$ and Message $m$:

  1. 1
    Hash Message: Compute the cryptographic digest $e = \operatorname{SHA-256}(m)$. Convert $e$ to integer $z$.
  2. 2
    Generate Ephemeral Scalar $k$: Select a cryptographically secure random integer $k \in [1, n-1]$.
  3. 3
    Compute Curve Point: Perform scalar point multiplication: $$(x_1, y_1) = k \times G$$
  4. 4
    Calculate $r$: $$r = x_1 \bmod n$$ If $r = 0$, pick another random $k$ and restart.
  5. 5
    Calculate $s$: Compute the modular inverse $k^{-1} \bmod n$, then: $$s = k^{-1} (z + d \cdot r) \bmod n$$ If $s = 0$, pick another random $k$ and restart.
  6. 6
    Output Signature: The resulting digital signature is the pair $(r, s)$.
Critical Engineering Warning (The Sony PS3 Flaw): The ephemeral key $k$ must NEVER be reused across two messages. If $k$ is repeated with private key $d$, an attacker can compute: $$s_1 - s_2 = k^{-1}(z_1 - z_2) \implies k = \frac{z_1 - z_2}{s_1 - s_2} \bmod n \implies d = \frac{s_1 k - z_1}{r} \bmod n$$ This instantly leaks the private key $d$! RFC 6979 provides deterministic $k$ generation to prevent this catastrophe.
B

ECDSA Signature Verification Algorithm

Executed by any Verifier (Bob) using Alice's Public Key $Q$, Message $m$, and Signature $(r, s)$:

  1. 1
    Range Verification: Confirm that integers $r$ and $s$ satisfy $1 \le r, s \le n-1$. If not, signature is immediately INVALID.
  2. 2
    Hash Message: Compute digest $e = \operatorname{SHA-256}(m)$ and extract integer $z$.
  3. 3
    Compute Modular Inverse: $$w = s^{-1} \bmod n$$
  4. 4
    Compute Intermediate Scalars: $$u_1 = z \cdot w \bmod n, \quad u_2 = r \cdot w \bmod n$$
  5. 5
    Compute Verification Point: $$(x_1, y_1) = u_1 \times G + u_2 \times Q$$ If $(x_1, y_1) = \mathcal{O}$ (point at infinity), signature is INVALID.
  6. 6
    Verify Equality: Compute $v = x_1 \bmod n$. $$\text{Result} = \begin{cases} \mathbf{VALID} & \text{if } v = r \\ \mathbf{INVALID} & \text{if } v \neq r \end{cases}$$
Why Does Verification Work? (Mathematical Proof)

Since $s \equiv k^{-1}(z + dr) \pmod n$, rearranging gives $k \equiv s^{-1}(z + dr) \equiv z w + d r w \equiv u_1 + u_2 d \pmod n$.

Substituting into curve arithmetic:

$$u_1 G + u_2 Q = u_1 G + u_2 (d G) = (u_1 + u_2 d) G = k G = (x_1, y_1)$$

Hence, the x-coordinate of the recovered curve point matches $r = x_1 \bmod n$ if and only if the private key and original message were genuine.

4.1 Secure Hash Algorithm 256 (SHA-256)

Signing large payloads directly with asymmetric scalar operations is computationally prohibitive. Therefore, ECDSA hashes the input payload into a 256-bit (32-byte) digest using SHA-256.

Crucial Properties of SHA-256:
  • Deterministic: The exact same input string will always yield the exact same 64-hex-character digest.
  • Pre-image Resistance (One-Way): Given digest $H$, it is computationally impossible to determine input $M$ such that $\operatorname{SHA-256}(M) = H$.
  • Second Pre-image Resistance: Given $M_1$, it is infeasible to find $M_2 \neq M_1$ such that $\operatorname{SHA-256}(M_1) = \operatorname{SHA-256}(M_2)$.
  • Collision Resistance: Infeasible to find any two arbitrary messages with identical digests ($2^{128}$ complexity via birthday attack).

4.2 The Avalanche Effect in Digital Signatures

A fundamental property of cryptographic hashes is the Avalanche Effect: changing as little as a single bit or character in the input message alters approximately 50% of the output bits completely pseudo-randomly.

Original: Hello, this is a secure message!
464d6db81bf83505c21966a014902a2444390b1ec1895a04bb4954e3d36b7582
Tampered: Hello, this is a tampered message!
34483a936a2eb6861501e4a6a12b4e5d666d63fbcc515a4aa311fbe4d95a975f

Because the digest changes completely, $z_{\text{tampered}} \ne z_{\text{original}}$, the scalar $u_1 = z \cdot w \bmod n$ lands on a completely different curve coordinate, causing $v \neq r$ and immediately invalidating the signature.

5.1 Advantages of ECDSA

  • Compact Key & Signature Sizes: 256-bit ECC key replaces 3072-bit RSA key. The signature is merely 64 bytes (compared to RSA's 384 bytes).
  • Reduced Computation Overhead: Scalar point multiplication requires dramatically fewer clock cycles than 3072-bit modular exponentiation in RSA.
  • Bandwidth & Battery Conservation: Perfect for resource-constrained embedded systems, smart cards, satellite links, and mobile wallets.
  • High Resistance to Known Quantum Attacks: While both RSA and ECC are vulnerable to Shor's algorithm on a large quantum computer, standard ECDSA on classical hardware offers superior security density per bit.

5.2 Real-World Engineering Applications

  • Blockchain Protocols: Bitcoin (secp256k1) and Ethereum use ECDSA to sign transactions and authorize decentralized asset transfers.
  • Transport Layer Security (TLS 1.3 / HTTPS): Modern web browsers and servers exchange ECDSA certificates for lightning-fast handshake authentication.
  • OpenSSH & Git Commit Signing: Developers use `ed25519` and `ecdsa-sha2-nistp256` keys to authenticate remote server access and verify git commits.
  • Mobile Hardware Enclaves: Apple Secure Enclave and Android Keystore store ECDSA private keys in hardware-isolated silicon for biometric authentication.

04 LAB PROTOCOL

Step-by-Step Laboratory Procedure

Standard operating procedure for performing the ECDSA experiment in the Virtual Cryptography Laboratory.

1
Step 1

Generate ECC Key Pair

Initialize the native browser Web Cryptography API. Invoke window.crypto.subtle.generateKey() specifying algorithm ECDSA with named curve P-256. Extract the 256-bit random private key scalar $d$ and compute the public key point $Q = d \times G$ consisting of $(x_Q, y_Q)$ coordinates.

Inputs: NamedCurve "P-256", Usages: ["sign", "verify"] Outputs: CryptoKeyPair (Private Key $d$, Public Key $Q$)
2
Step 2

Enter Message

Provide an arbitrary digital message or transaction text into the simulation input field. The default benchmark message is Hello, this is a secure message!. Encode the characters into UTF-8 byte stream using TextEncoder().

Inputs: UTF-8 String Outputs: Uint8Array Buffer
3
Step 3

Generate SHA-256 Hash

Invoke window.crypto.subtle.digest("SHA-256", messageBuffer). Observe the transformation of the variable-length UTF-8 payload into a fixed 256-bit (64-character hexadecimal) cryptographic digest $e$.

Inputs: Message Bytes Outputs: 32-Byte SHA-256 Digest ($e$)
4
Step 4

Generate Digital Signature

Execute window.crypto.subtle.sign() with private key $d$ and hash $e$. The algorithm generates ephemeral key $k$, computes point $k \times G$, extracts $r = x_1 \bmod n$, and calculates $s = k^{-1}(e + dr) \bmod n$. Deconstruct the output into distinct 32-byte components $r$ and $s$.

Inputs: Private Key $d$, SHA-256 Hash $e$ Outputs: IEEE P1363 Signature ($r \parallel s$)
5
Step 5

Verify Signature

Execute window.crypto.subtle.verify() passing the original message bytes, public key $Q$, and signature $(r, s)$. Confirm that $u_1 G + u_2 Q$ lands on point $(x_1, y_1)$ with $x_1 \bmod n = r$, yielding Signature Verified (Valid) with a green indicator.

Inputs: Public Key $Q$, Message Bytes, Signature Buffer Outputs: Boolean Verification Result (true)
6
Step 6

Modify Message (Tamper Test)

Inject an intentional message corruption by clicking "Tamper Message", altering the payload to Hello, this is a tampered message!. Observe the dramatic divergence in the SHA-256 hash output caused by the avalanche effect.

Inputs: Corrupted Payload String Outputs: Divergent Hash Digest
7
Step 7

Verify Again & Conclude

Execute signature verification on the tampered message against the original signature. Observe the immediate failure: Signature Invalid (Rejected) with a red indicator. Reset the experiment to restart the cycle.

Inputs: Corrupted Message, Original Signature, Public Key Outputs: Boolean Verification Result (false)

06 EXPERIMENTAL SUMMARY

Conclusion & Key Findings

Formal academic summary of experimental observations, cryptographic properties verified, and engineering conclusions.

Experimental Conclusion

Validated Engineering Hypotheses

Through this virtual laboratory experiment, the implementation of the Elliptic Curve Digital Signature Algorithm (ECDSA) over the NIST P-256 curve using SHA-256 hashing was successfully demonstrated and verified.

  • Asymmetric Key Derivation: Verified that generating public key $Q = d \times G$ from a 256-bit private scalar $d$ is computationally trivial ($O(\log n)$), while deducing $d$ from $Q$ requires solving the ECDLP ($O(\sqrt{n})$), providing robust cryptographic security.
  • Mathematical Integrity & Verification: Successfully confirmed that authentic signatures yield $u_1 G + u_2 Q = (x_1, y_1)$ such that $x_1 \bmod n = r$, confirming sender origin and payload authenticity.
  • Avalanche Tamper Detection: Confirmed that even modifying a single character in the message produces a totally distinct SHA-256 digest, which shifts the scalar linear combination $u_1 G + u_2 Q$ away from the signature's ephemeral point $r$, causing immediate cryptographic rejection.
  • Efficiency Superiority: Demonstrated that ECDSA provides 128-bit security margin with only 64-byte signatures, making it substantially more efficient than traditional RSA algorithms.
