01 LAB AIM & SCOPE

Aim of the Experiment

Comprehensive study, mathematical analysis, and practical execution of Elliptic Curve Digital Signature Algorithm (ECDSA) for asymmetric origin verification and integrity protection.

Primary Statement of Aim

Experiment Focus: Asymmetric Cryptography

To implement, execute, and verify the Elliptic Curve Digital Signature Algorithm (ECDSA) using the NIST P-256 (secp256r1) elliptic curve and SHA-256 cryptographic hashing via the native browser Web Cryptography API.

The experiment aims to provide undergraduate and postgraduate engineering students with hands-on insight into private scalar generation, public point derivation ($Q = d \times G$), ephemeral scalar signing, signature verification ($v \stackrel{?}{=} r$), and the strict detection of message tampering (avalanche effect).

02 THEORETICAL FOUNDATIONS

Cryptographic Theory of ECDSA

Student-friendly introduction to cryptography, elliptic curves, digital signatures, and their real-world applications.

What is Cryptography?

Cryptography is the science of protecting digital information by transforming readable text into secret code. It ensures that only authorized people can access the information. Digital signatures use this technology to prove who sent a message and that the message hasn't been changed.

  • Confidentiality: Only the intended recipient can read the message.
  • Integrity: The message cannot be changed without detection.
  • Authenticity: We can verify who actually sent the message.
  • Non-Repudiation: The sender cannot deny sending the message.

What is Elliptic Curve Cryptography (ECC)?

Elliptic Curve Cryptography is a modern method for public-key cryptography. It uses mathematical curves instead of traditional number-based systems. ECC provides the same security as older systems like RSA but with much smaller keys, making it faster and more efficient.

  • Smaller Keys: A 256-bit ECC key provides the same security as a 3072-bit RSA key.
  • Faster Operations: Smaller keys mean faster calculations and less computing power.
  • Less Storage: Takes up less space in memory and on disk.
  • Perfect for Mobile: Ideal for smartphones and devices with limited resources.

How ECDSA Works

The Elliptic Curve Digital Signature Algorithm (ECDSA) allows a sender to sign a message using their private key. Anyone can verify this signature using the sender's public key. This ensures the message is authentic and has not been modified.

Signing Process:
  • The sender hashes their message using SHA-256.
  • The sender uses their private key to create a unique signature.
  • The signature is sent along with the message.
Verification Process:
  • The receiver hashes the received message using SHA-256.
  • The receiver uses the sender's public key to verify the signature.
  • If the signature matches, the message is authentic and unchanged.

SHA-256 Hashing

SHA-256 is a cryptographic hashing algorithm that converts any message into a fixed-length 256-bit (64 hex character) digest. This digest is unique to the original message. Even a tiny change in the message produces a completely different hash.

  • Deterministic: The same input always produces the same hash.
  • One-Way: You cannot reverse the hash to find the original message.
  • Unique: Different messages produce different hashes.
  • Avalanche Effect: Changing one character changes approximately 50% of the hash output.

Advantages of ECDSA

  • Compact Keys: Smaller keys than RSA with equivalent security.
  • Faster Performance: Requires less computing power and time.
  • Efficient: Saves bandwidth, battery, and storage space.
  • Modern Standard: Widely adopted in current security systems.

Real-World Applications

  • Blockchain: Bitcoin and Ethereum use ECDSA for transaction signing.
  • Web Security: HTTPS and TLS 1.3 use ECDSA for secure connections.
  • Software Development: Git commit signing and SSH authentication.
  • Mobile Security: Apple Secure Enclave and Android Keystore use ECDSA.

04 LAB PROTOCOL

Step-by-Step Laboratory Procedure

Standard operating procedure for performing the ECDSA experiment in the Virtual Cryptography Laboratory.

1
Step 1

Generate ECC Key Pair

Initialize the native browser Web Cryptography API. Invoke window.crypto.subtle.generateKey() specifying algorithm ECDSA with named curve P-256. Extract the 256-bit random private key scalar $d$ and compute the public key point $Q = d \times G$ consisting of $(x_Q, y_Q)$ coordinates.

Inputs: NamedCurve "P-256", Usages: ["sign", "verify"] Outputs: CryptoKeyPair (Private Key $d$, Public Key $Q$)
2
Step 2

Enter Message

Provide an arbitrary digital message or transaction text into the simulation input field. The default benchmark message is Hello, this is a secure message!. Encode the characters into UTF-8 byte stream using TextEncoder().

Inputs: UTF-8 String Outputs: Uint8Array Buffer
3
Step 3

Generate SHA-256 Hash

Invoke window.crypto.subtle.digest("SHA-256", messageBuffer). Observe the transformation of the variable-length UTF-8 payload into a fixed 256-bit (64-character hexadecimal) cryptographic digest $e$.

Inputs: Message Bytes Outputs: 32-Byte SHA-256 Digest ($e$)
4
Step 4

Generate Digital Signature

Execute window.crypto.subtle.sign() with private key $d$ and hash $e$. The algorithm generates ephemeral key $k$, computes point $k \times G$, extracts $r = x_1 \bmod n$, and calculates $s = k^{-1}(e + dr) \bmod n$. Deconstruct the output into distinct 32-byte components $r$ and $s$.

Inputs: Private Key $d$, SHA-256 Hash $e$ Outputs: IEEE P1363 Signature ($r \parallel s$)
5
Step 5

Verify Signature

Execute window.crypto.subtle.verify() passing the original message bytes, public key $Q$, and signature $(r, s)$. Confirm that $u_1 G + u_2 Q$ lands on point $(x_1, y_1)$ with $x_1 \bmod n = r$, yielding Signature Verified (Valid) with a green indicator.

Inputs: Public Key $Q$, Message Bytes, Signature Buffer Outputs: Boolean Verification Result (true)
6
Step 6

Modify Message (Tamper Test)

Inject an intentional message corruption by clicking "Tamper Message", altering the payload to Hello, this is a tampered message!. Observe the dramatic divergence in the SHA-256 hash output caused by the avalanche effect.

Inputs: Corrupted Payload String Outputs: Divergent Hash Digest
7
Step 7

Verify Again & Conclude

Execute signature verification on the tampered message against the original signature. Observe the immediate failure: Signature Invalid (Rejected) with a red indicator. Reset the experiment to restart the cycle.

Inputs: Corrupted Message, Original Signature, Public Key Outputs: Boolean Verification Result (false)

06 EXPERIMENTAL SUMMARY

Conclusion & Key Findings

Formal academic summary of experimental observations, cryptographic properties verified, and engineering conclusions.

Experimental Conclusion

Validated Engineering Hypotheses

Through this virtual laboratory experiment, the implementation of the Elliptic Curve Digital Signature Algorithm (ECDSA) over the NIST P-256 curve using SHA-256 hashing was successfully demonstrated and verified.

  • Key Generation: Successfully generated a public key from a private key using elliptic curve mathematics. The private key remains secret while the public key can be freely shared.
  • Message Signing: Created a digital signature by combining the private key with the message hash. This signature proves the message came from the sender.
  • Message Verification: Verified that the signature is valid using the public key. If the message is changed even slightly, verification fails.
  • Tamper Detection: Confirmed that any modification to the message produces a different hash, causing the signature verification to fail. This ensures message integrity.
